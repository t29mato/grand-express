# 世界マップの設計(共通の前提)

`scripts/countries/world/` に、他国と同じ形の国パックとして作る。手本は `scripts/countries/france/`。

## 投影(決定済み・変更しないこと)

```js
export const WORLD_PROJ = {
  BW: 3300, BH: 1210,
  LON0: -170, LON1: 190,   // 西端は太平洋、東端も太平洋(日付変更線をまたがない)
  LAT0: 75,  LAT1: -56,
  seg: 150,
};
```

- 経度が -170 未満になる都市は置かない(日付変更線の処理を避けるため)。
  ハワイ(-157.9)やオークランド(174.8)は範囲内なので使える。
- 緯度は北緯75〜南緯56。南極大陸は入れない。

## 「都市」の単位

**都市**にする(国ではない)。既存の仕組み(物件2件・豆知識・地方)がそのまま使えるため。
ただし世界規模なので、その国を代表する1〜3都市に絞る。

## 地方(6区分)

`eur` ヨーロッパ / `asi` アジア / `afr` アフリカと中東 / `nam` 北アメリカ /
`sam` 南アメリカ / `oce` オセアニアと太平洋

## 路線の種類

- **陸続きなら陸路、海をまたぐなら航路**(`"sea"`。edges の第3要素)。これが第1原則。
- **空路の概念は追加しない。** 既存の EdgeKind は rail/sea のみで、増やすと盤面の描き分け・
  テスト・セーブまで波及する。海をまたぐ移動はすべて船、という建て付けにする。
- **地方の区分(eur/asi/afr...)と、地続きかどうかは別の話。**
  カイロ(afr)–エルサレム(asi)はシナイ半島で地続きなので陸路。
  モスクワ(eur)–ウランバートル(asi)もシベリア鉄道で陸路。
  「大陸をまたぐから航路」と機械的に決めると、シベリア鉄道を船で描くことになる。

## 日付変更線

投影が経度 -170〜190 なので、**太平洋は盤面の左右の端に割れる。**
世界地図のほとんどが取っている形(大西洋を中心に置く)で、継ぎ目が
日付変更線にあるのは普通のこと。

ホノルル(-157.9)・パペーテ(-149.6)は左端、オークランド(174.8)・
スバ(178.4)は右端に来る。**この二つを結ぶ辺は張らない。**
張ると盤面を横断する線が引かれ、地図として嘘になる。

そのため「世界一周」という名前だが、盤面の上で文字どおり輪にはならない。
端から端まで行き来できれば目的は果たせる。

**ただし全体が連結していること。** 太平洋の東端(→サンフランシスコ)と
西端(→アジア)がそれぞれ本体につながっていれば、輪でなくても全都市に行ける。
孤立した島の塊があると、目的地に選ばれたときにたどり着けなくなる。
`board-movement-invariants.test.ts` が機械的に検査している。
