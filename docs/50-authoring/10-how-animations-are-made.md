# 動く絵の作り方 — 全体像と、踏んだ落とし穴

このゲームには**246本**の動く絵が入っている(2026-08-07 時点)。
すべて手書きのSVG + CSSアニメーションで、外部の画像もライブラリも使っていない。

この文書は「どうやって作っているか」を最初から説明する。
個別の仕様は [02](./02-animation-guide.md) / [03](./03-season-animation-guide.md) /
[04](./04-doom-animation-guide.md) / [05](./05-city-scene-guide.md) にあるので、
ここでは**なぜそうしているのか**と、**実際に何を間違えたか**を書く。

## 1. 4種類の絵と、それぞれが出る場所

| 種類 | 置き場所 | 本数 | いつ出るか | 背景 |
|---|---|---|---|---|
| 出来事 | `events/animations/` | 84 | 青マス・赤マスに止まったとき | 描く |
| 季節 | `events/seasons/` | 60 | 月が替わったとき | 描く |
| 厄災 | `events/dooms/` | 35 | 厄災の神に取り憑かれた人に災難が起きたとき | 描く |
| 都市の層 | `city/scenes/` | 67 | 都市カードを開いているあいだずっと | **描かない** |

前の3つは「モーダルの中で数秒見せる、独立した1枚の絵」。
最後の1つだけ性格が違い、**既存の静止画に重ねる透明な層**になっている。

### なぜ都市だけ「重ねる層」なのか

都市の背景67種は legacy の単一HTMLから抽出した静止SVGで、これは凍結している。
動きを足すのに2つの道があった。

1. 67枚を描き直して動きを埋め込む
2. 静止画はそのままにして、上に透明な層を1枚重ねる

**2を選んだ。**(コミット `db80565`)理由は2つ。

- 67枚を描き直すと、既存の絵が壊れるリスクを67回引く。重ねるだけなら下の絵は無傷
- 足すのは「その土地らしい動き」だけでよく、1枚あたりが小さく済む

合成は `city-art.tsx:42-78` でやっている。静止SVGを `dangerouslySetInnerHTML` で敷き、
その上に `.city-art-overlay`(`position:absolute; inset:0`)で層を重ねる。

```tsx
// city-art.tsx より
const overlay = citySceneOverlayFor(context.content.id, city.artSceneKey);
...
<div className="city-art-stack">
  <svg viewBox="0 0 400 246" dangerouslySetInnerHTML={{ __html: inner + caption }} />
  {overlay && <div className="city-art-overlay with-caption">{createElement(overlay)}</div>}
</div>
```

`with-caption` が付くのは、都市カードの下端36pxが**都市名の帯**だから。
ここに波やかもめが被ると名前が読めなくなるので、`bottom: 14.6%`(= 36/246)で層を持ち上げている。

> **`createElement` を使っているのはlint対策。**
> `const Scene = ...; <Scene />` と書くと「描画のたびにコンポーネントを定義している」と
> react-hooks のルールに判定される。`season-modal.tsx:27-29` にその旨のコメントがある。

## 2. 全部に共通する7つの約束

どの種類でも同じ。これはテストで機械的に検査している(後述)。

1. **`viewBox="0 0 400 210"` 固定。** `width`/`height` 属性は付けない
   → モーダルの中で絵ごとに大きさが変わらないため
2. **自己完結。** 外部画像・フォント・ライブラリを使わない。SVG図形と `<style>` だけ
   → オフラインやCSPで壊れないため
3. **`<style>{`...`}`** にキーフレームを直接書く
4. **無限ループ**(`animation: ... infinite`)
   → モーダルが開いている数秒のあいだ流れ続ける
5. **`prefers-reduced-motion` で止まる**
6. **`role="img" aria-hidden="true"`。文字(`<text>`)は描かない**
   → 説明文は4言語で別に表示される。絵に文字を焼くと翻訳できない
7. TypeScript。`"use client"` は不要(親がclient)

都市の層だけ追加で2つ:

8. **背景を塗りつぶさない。** `<rect width="400" height="210">` を置くと下の絵が全部隠れる
9. **控えめにする。** 都市カードは読み物なので、動きが主張すると文字が読みにくい

## 3. 1本作る手順

### 3.1 ファイルを置く

ファイル名がそのまま登録簿の鍵になる。ここは例外を作らないこと(理由は §7)。

| 種類 | ファイル名 | 関数名 |
|---|---|---|
| 出来事 | `<出来事ID>.tsx` | PascalCase |
| 季節 | `<国>-<月2桁>.tsx`(月は0始まりで **0=4月**) | `Japan02` |
| 厄災 | `<国>-<厄災ID>.tsx` | `JapanTyphoon` |
| 都市 | `<国>-<背景キー>.tsx` | `JapanPort` |

named export を1つだけ。default export にしない。

### 3.2 焼いて見る

```
npm run preview -- <tsxのパス> <出力png> [待ち時間ms]
```

盤面を進めて目的のマスに止まるのを待たなくても、1本だけ描いて確認できる。
既定で1800ms待ってから撮るので、その瞬間の姿が写る。

### 3.3 直す → 登録

登録簿(`index.ts`)は**自分で編集しない**。取りまとめ側が生成器を回す:

```
node scripts/generate-animation-registries.mjs
```

## 4. SVGの落とし穴(全部、実際に踏んだもの)

### 4.1 CSSキーフレームの `transform` は、SVGの `transform` 属性を上書きする

**症状:** アニメーションが始まった瞬間、図形が画面の左上へ飛ぶ。

SVGの `transform="translate(346,172)"` 属性と、CSSの `@keyframes` 内の `transform` は
**同じプロパティを取り合う**。CSSが勝つので、位置決めが消える。

**対策: 位置は外側の `<g transform>`、動きは内側の要素、と層を分ける。**

```tsx
// japan-port.tsx — 正しいかたち
<g transform="translate(346,172)">     {/* 位置決め。CSSは触らない */}
  <g className="jpt-boat">             {/* 動き。CSSがtransformを使う */}
    <path d="M-15,0 L15,0 L11,7 L-11,7 Z" fill="#f0e6d2" />
  </g>
</g>
```

もう一つのやり方は、**位置決めもCSS側でやってしまう**こと。
見本の `shiretoko-bear.tsx` はこちら:

```css
.runner { transform: translate(120px, 150px); animation: flee 1.5s ease-in-out infinite; }
@keyframes flee {
  0%, 100% { transform: translate(120px, 150px); }   /* ← 座標を書き直している */
  50%      { transform: translate(104px, 143px); }
}
```

キーフレームの中で毎回 `translate(120px,150px)` を書き直しているのは、
書かないと原点へ飛ぶから。どちらでもよいが、**混ぜると壊れる。**

### 4.2 `transform-box: fill-box` と `transform-origin` が要る

**症状:** 腕や脚が胴から外れて飛んでいく。煙があらぬ方向へ膨らむ。

これが**いちばん多く踏んでいる**落とし穴で、少なくとも3回まとめて直している。

- `0b78931` ブラマプトラ増水の煙が「あらぬ方向へ飛んでいた」
- `1ea0cd5` 4本まとめて修正(「担当エージェントの後追い修正」)
- `6378ffe` 都市の層で **12ファイル23か所**

**なぜ起きるか。** SVG要素の `transform-box` の既定値は `view-box`。
つまり `transform-origin: 50% 0` と書くと、パーセントは**その図形の大きさではなく
SVG全体(400×210)に対して**解決される。原点は (200, 0) — 図形とは無関係な場所だ。
そこを軸に回すので、図形は遠くへ振り飛ばされる。

`transform-box: fill-box` を書くと、はじめてパーセントが**その図形自身の外接矩形**に
対して解決される。

```css
/* 誤り: 原点が (200,0) に解決され、脚が振り飛ばされる */
.leg-a { animation: stride 0.35s linear infinite; transform-origin: 50% 0; }

/* 正しい: 原点が脚自身の上端中央になる */
.leg-a { transform-box: fill-box; transform-origin: 50% 0; animation: stride 0.35s linear infinite; }
```

**実際に再現した例。** 見本の `shiretoko-bear.tsx` を `npm run preview` で焼くと、
旅人の脚とヒグマの前足が胴から外れて、地面に落ちた別の物体のように見える。
`transform-box: fill-box` を4か所足したコピーを焼くと、脚も前足も胴に付いた。
差はこの1行だけ。

> **注(2026-08-07 時点の実測):** `transform-origin` を割合・キーワードで書きながら
> `transform-box` が無い箇所が、246本中55ファイル・90か所ある。
> ただし**全部が目に見えて壊れているわけではない**。図形が偶然 (200,0) の近くにあれば
> ずれは小さい。実際 `desalpe.tsx`(牛の脚)と `chasse-croise.tsx`(腕)を焼いてみたが、
> 見た目の破綻は確認できなかった。
> **数えられるのは「疑わしい箇所」までで、壊れているかは焼いて見るまで分からない。**

`transform-origin` を `px` などの絶対値で書く場合は `transform-box` が無くても正しく動く
(実測62か所)。割合・`center`・`top` などを使うときだけ必要になる。

### 4.3 `<style>` はページ全体に効く

**症状:** 別の絵のアニメーションが、こちらの図形にかかる。

SVGの中に書いた `<style>` にもスコープは無い。**ページ全体に効く。**
都市カードでは静止画と重ねの層が同時に出るし、モーダルが複数開くこともある。

**対策: クラス名と `@keyframes` 名の両方に、そのファイル固有の接頭辞を付ける。**

```
japan-port.tsx      → .jpt-wave   @keyframes jpt-drift
japan-02.tsx        → .j02-rain   @keyframes j02-pour
india-megacity.tsx  → .imeg-haze  @keyframes imeg-drift-a
```

`@keyframes` 名を忘れやすい。クラス名だけ変えても、キーフレーム名が衝突すれば
**動きだけが別の絵のものに入れ替わる**。原因がとても分かりにくい。

コミット `6378ffe` では、インドの各シーンの接頭辞を `meg-` → `imeg-` のように
一括で付け替えている。当時まだ衝突は起きていなかったが、シーンが増えるほど
ぶつかる余地が出るため、先回りして直した。

**確認のしかた。** 246本を横断して名前の重複を数える:

```bash
python3 - <<'EOF'
import re,glob,collections
cls=collections.defaultdict(set); kf=collections.defaultdict(set)
for d in ["src/presentation/components/events/animations",
          "src/presentation/components/events/seasons",
          "src/presentation/components/events/dooms",
          "src/presentation/components/city/scenes"]:
    for f in glob.glob(d+"/*.tsx"):
        m=re.search(r'<style>\{`(.*?)`\}</style>', open(f).read(), re.S)
        if not m: continue
        for c in re.findall(r'\.([A-Za-z][\w-]*)', m.group(1)): cls[c].add(f)
        for k in re.findall(r'@keyframes\s+([\w-]+)', m.group(1)): kf[k].add(f)
print("重複クラス:", {k:v for k,v in cls.items() if len(v)>1})
print("重複keyframes:", {k:v for k,v in kf.items() if len(v)>1})
EOF
```

2026-08-07 時点では、クラス名3405種・`@keyframes` 名1569種で**重複ゼロ**。
接頭辞の約束は守られている。

### 4.4 描画順と重なり — 先に書いたものが下になる

SVGにz-indexは無い。**JSXに書いた順がそのまま重ね順**で、後に書いたものが上に来る。

実際に直した2件は、どちらも「順番」そのものより**重なりかたが誤解を生んだ**例だった。

**(a) 差し出した腕が胴に埋もれた**(`213a79a` `standing-between.tsx`)

窓口へ差し出す腕を描いたが、胴と同じ色(`#f5b31c`)で、位置も胴に食い込んでいた。
腕はちゃんと描かれているのに、**見た人には腕が無いように見える**。

```diff
- <rect x="16" y="-46" width="9"  height="30" rx="4.5" fill="#f5b31c" />  {/* 胴と同色 */}
+ <rect x="19" y="-48" width="10" height="32" rx="5"   fill="#d99a0c" />  {/* 外へ出し、濃くした */}
```

**同じ色の図形が隣り合うと、1つの塊に見える。** 重なる部分は色を変える。

**(b) 硬貨が帆に貼りついて見えた**(`7a1c852` `dhow-cargo.tsx`)

宙に舞う硬貨を描いたが、置いた場所が帆の真上だった。硬貨は帆より後に描かれている
ので手前にあるのだが、大きな不透明の図形に重なると**貼りついているように見える**。

```diff
- <circle className="dhw-coin-a" cx="252" cy="84" r="8" />   {/* 帆の上 */}
+ <circle className="dhw-coin-a" cx="150" cy="58" r="8" />   {/* 空の上 */}
```

**浮いているものは、周りに空きが要る。** 重ね順を直すのではなく、置き場所を変えて直した。

## 5. 確認のしかた(ここがいちばん大事)

**型検査もlintもテストも、絵が正しく見えるかは一切見ていない。**
色が変でも、腕が飛んでいても、全部緑になる。だから**焼いて目で見る**しかない。

### 5.1 1本だけ見る — `npm run preview`

```
npm run preview -- src/presentation/components/events/seasons/japan-02.tsx /tmp/a.png
```

**この道具自体が一度壊れていた。**(`027f12b`)
以前はJSXから `<svg>…</svg>` を正規表現で切り出して描いていた。そのため
`{list.map(...)}` で作る要素が**描かれないまま静かに消えていた**。
紙吹雪や後光がごっそり抜けた絵を「確認できた」と誤認していたし、
サブエージェントにもそれで確認させていた。

いまは Vite で本当にコンポーネントを組み立てて描いている。描画中のJSエラーも拾って
終了コードを立てる。**繰り返しで作る部分がちゃんと出ているか、必ず目で確かめること。**

### 5.2 都市の層は、単体で見ても判断できない

これが preview の限界。`japan-port.tsx` を単体で焼くと、こう写る:

- 紫の背景(これは preview の台紙であって、絵の一部ではない)
- 波の筋が5本、かもめが2羽、小舟が1隻。**それだけ**

小舟が水面に載っているのか宙に浮いているのか、かもめの高さが空の範囲に収まっているのか、
**この絵からは分からない。** 下の静止画が無いからだ。

### 5.4 テストが見ているのは「形式」だけ

`animations.test.ts` / `seasons.test.ts` / `dooms.test.ts` / `scenes.test.ts` が
全246本を機械的に検査している。見ているのはこれだけ:

| 検査 | 落ちる理由 |
|---|---|
| `viewBox="0 0 400 210"` | 絵ごとに大きさが変わる |
| `prefers-reduced-motion` の文字列がある | 止められない |
| `<text>` を使っていない | 翻訳できない |
| `animation: ... infinite` がある | 途中で止まる |
| `aria-hidden` がある | 読み上げが絵を読む |
| `https?://` を含まない | オフライン・CSPで壊れる |
| `index.ts` に全ファイルが登録されている | 静かに汎用の絵にフォールバックする |
| (都市のみ)`width="400" height="210"` の `<rect>` が無い | 下の絵を隠す |
| (都市のみ)その国の全背景キーに層がある | その背景の都市だけ静止する |
| (厄災のみ)3か国×7種が揃っている | その災難だけ絵が出ない |

**逆に言うと、これ以外は何も見ていない。**
色が不正でも、図形が画面外でも、腕が胴に埋もれていても、テストは通る。

「登録されているか」を機械で見ているのは、**登録漏れが静かに起きる**から。
出来事の絵が無いと汎用の「+/−が浮くだけの絵」にフォールバックする(`event-animation.tsx:15`)。
エラーにならないので、放っておくと誰も気づけない。

## 6. 子ども向けの方針 — 厄災は「破壊」ではなく「慌てている様子」

厄災は災難の絵だが、**子どもも遊ぶので怖がらせない。**
痛みや破壊そのものを描かず、**慌てている / 困っている様子**で伝える。

| 出来事 | 描くもの | 描かないもの |
|---|---|---|
| 地震 | 建物が揺れて棚から食器が落ちる | 倒壊した瓦礫 |
| 火事 | 煙と逃げる人 | 焼ける人 |
| スリ | 手が伸びて財布が飛ぶ | 暴力 |
| 台風 | 裏返る傘、赤く染まる時刻表 | 被災した街 |

`japan-typhoon.tsx` が分かりやすい。描いてあるのは
**止まったままの電車・赤い信号・一斉に赤くなった時刻表・下りるシャッター**で、
壊れたものは一つも無い。「困った、動かない」という状況だけで台風を表している。

色でも支える。全体に暗めの地色を使い、赤(`#e05252`)を差し色にすると災難らしくなる。

> この方針は登録簿の生成器(`generate-animation-registries.mjs`)の雛形にも
> 書き込んである。一度、生成器が味気ない文言に上書きしてしまい、
> `6c075b3` で元の文言を雛形へ戻している。**方針は消えると忘れられる。**

出来事・季節の絵では、金額が増える話は明るく、減る話は少し暗い地色にすると伝わる。

## 7. `prefers-reduced-motion` への対応

動きに弱い人(乗り物酔い・前庭障害・光過敏など)のために、
OS側で「視差効果を減らす」を有効にしている人には**動きを止める**。

**末尾に必ず置く:**

```css
@media (prefers-reduced-motion: reduce) {
  .jpt-wave, .jpt-boat, .jpt-gull-a, .jpt-gull-b, .jpt-flap-a, .jpt-flap-b { animation: none; }
}
```

守ること2つ。

**(a) 止めた状態でも「何が起きたか」が絵として分かる構図にする。**
動きが止まると意味が消える絵(光が動くだけ、パーティクルが流れるだけ)は作らない。
具体物を置いて、静止画としても成立させる。

**(b) 動いているクラスを漏らさず並べる。**
テストは「`prefers-reduced-motion` という文字列があるか」しか見ていないので、
1つ書き忘れても緑になる。

書き方は2通りあり、どちらでもよい:

```tsx
{/* 要素に「基準クラス + 変種クラス」を付ける */}
<path className="frcap-car frcap-r1" ... />
<path className="frcap-car frcap-r2" ... />
```
```css
.frcap-r1 { animation: frcap-right 6.5s linear infinite; }
.frcap-r2 { animation: frcap-right 9s   linear infinite; animation-delay: -4s; }

@media (prefers-reduced-motion: reduce) {
  .frcap-car { animation: none; }   /* 基準クラスだけ止めれば全部止まる */
}
```

これが効くのは、**メディアクエリを末尾に置いているから**。
`.frcap-r1` と `.frcap-car` は詳細度が同じ(0,1,0)なので、後に書いたほうが勝つ。
**メディアクエリを途中に置くと、この書き方は黙って効かなくなる。**

2026-08-07 時点で全246本を要素単位で調べたところ、

## 8. 複数人で作るときの決まり

絵はまとまった本数を、複数のサブエージェントに分担させて作っている。
記録が残っているのは `6e8799d` で、**6体に8本ずつ**割り当てて49本を作った。
そのときの約束。

### 8.1 登録簿(`index.ts`)は取りまとめ側だけが触る

**同じファイルを同時に編集すると壊れる。上書き事故が実際に起きている。**

作り手は**新規ファイルだけ**を置く。登録は取りまとめ側が生成器で一括して行う:

```
node scripts/generate-animation-registries.mjs
```

手で書き写さないのは、生成器のコメントにこうあるとおり:

> その1人が62本を手で書き写すと、いつか必ず1本落とす。ここで機械的に作れば落ちない。

### 8.2 ファイル名 = 登録簿の鍵。例外を作らない

生成器は**ファイル名から鍵とコンポーネント名を作る**。だから例外は事故になる。

`588a2f1` がその実例。ヒグマの絵だけ、ファイル名 `bear-attack` と出来事ID
`shiretoko-bear` がずれていた。手書きの登録簿では意図的な別名として通っていたが、
生成に切り替えた瞬間**この1件だけ絵が消える**。

> 別名表を足すより、例外そのものを無くすほうが後で壊れない。

としてファイル名のほうを `shiretoko-bear.tsx` に改名した。

同じ性質の問題がもう1件。背景キーに `megacity_asia` があり、生成器がハイフンだけで
区切っていたため `WorldMegacity_asia` という実在しない名前を作っていた(`6c075b3`)。
いまは `[-_]` の両方で区切る。

### 8.3 分担するときに渡すもの

- 仕様(§2の7つ)
- **見本を1本**。文章で説明するより、実物を1本読ませるほうが揃う
- 触ってよいディレクトリ。それ以外は触らせない

### 8.4 まとめて作る前に、少しだけ作って見せる

プロジェクト全体の決まりでもある(`CLAUDE.md`)。
**77都市を書いてから「多すぎた」となって丸ごと捨てたことがある。**
方向が違っていたときに捨てる量を小さくするため、まず5本だけ作って見せる。

## 9. 色

ゲームの絵柄に揃える。平たい塗り、輪郭線は暗色、1枚あたり3〜6色程度。

| 用途 | 色 |
|---|---|
| 空 | `#8fc4e8`(晴) 〜 `#20364a`(夜・荒天) |
| 地面 | `#2f4a33`(草) / `#c9a877`(土・砂) |
| 人の顔 | `#f6efe2` |
| 金・強調 | `#f5b31c` |
| 赤・危険 | `#e8443f` / 厄災は `#e05252` |
| 青 | `#5b8fe8` |

`#5b8fe8` のような色コードは**ただの文字列**で、型検査もlintも中身を見ない。
綴りを間違えても静かに「色なし」として描画されるだけなので、
ここでも**焼いて目で見る**以外に見つける方法はない。

## 10. まとめ — 手順として

1. 仕様(§2)を守って1ファイル置く
2. `npm run preview` で焼く → **画像を開いて目で見る**
3. 都市の層なら、`npm run shot -- <国> city` で**合成した状態でも見る**
4. `transform-box` / 接頭辞 / 重なり(§4)を見直す
5. `prefers-reduced-motion` で止まるか、止めても意味が伝わるか確かめる
6. 取りまとめ側が生成器を回して登録
7. `npm run check` を通す

**測ってから語ること。** この文書の数字(246本・90か所・重複ゼロ)は
すべて実際に数えたもので、推測は含まない。
プロジェクトの決まりでもある —「原因を推測で語らない。まず計測する。」
