# コンテンツの書き方

都市・クイズ・出来事などの文章とデータを足すときの決まり。

## どこに書くか

`legacy/grand-express.html` は**アーカイブとして凍結**しており、書き換えない。
追加・変更はすべて抽出後にマージされる層に置く。

| 置き場所 | 用途 |
|---|---|
| `scripts/content-overrides/` | legacy 由来の国(ボリビア・日本)への追加・修正 |
| `scripts/countries/<国>/` | legacy に無い、このリポジトリで書き起こした国(インド) |

どちらも `node scripts/extract-legacy-content.mjs` で
`src/infrastructure/content/*.content.json` に焼き込まれる。**JSONを直接編集しない。**

## 4言語

`t("en|es|fr|ja")` の形で必ず4言語そろえる。分けられなければその場でエラーになる。

機械的な直訳にしない。英語で2文なら、日本語も2文で自然に読める形にする。
語順や言い回しは言語ごとに変えてよい。

## 豆知識(`fact`)の粒度

**1文目でその土地に固有の事実、2文目でその背景か現在の姿。**

良い例(白川郷):
> 茅葺きの屋根は4mの雪を落とすため60度に葺かれ、村総出で順に葺き替える。
> 屋根裏では養蚕が営まれ、それが建材の費用を賄った。

悪い例:
> 美しい合掌造りの集落です。世界遺産に登録されています。

「どこにでも書ける文」は書かない。数字・年号・固有名詞のどれかは入れる。
外国から来た人と一緒に遊んで、**お互いに知らないことがある**水準を狙う。

## 都市

`city(名前, 経度, 緯度, 地方, mark, bg, ラベル位置, ひとこと, 豆知識, [物件2件])`

- 経度・緯度は**実際の値**を使う。投影の範囲外や海の上に出るとテストで落ちる。
- `mark` / `bg` は既存のキーから選ぶ(`src/infrastructure/content/<国>.content.json` の
  `marks` / `bg` にキー一覧がある)。新しい絵が要るなら board-artist に依頼する。
- 物件はちょうど2件。

## クイズ

難易度1〜10。基準は「**その国の外にいる一般的な人**がどれくらい答えられそうか」。

- 1〜3 … 知らなくても常識や推測で当たる
- 4〜6 … 旅行したり少し調べたことがあれば分かる
- 7〜8 … 文化・歴史に踏み込んだ知識が要る
- 9〜10 … 現地の人か、強い関心のある人でないと難しい

選択肢は3つ。正解の位置は偏らないよう散らす。

## 出来事(青マス・赤マス)

`ev(id, kind, [地方], 絵文字, 金額, 題, 説明)`

- **ルーレットの代わりに理由を与えるのが目的。** その地方で実際に起こりそうな話にする。
- 地方を指定しなければ全国どこでも出る。土地に強く結びついた話だけ絞る。
- どの地方でも `gain` と `loss` が最低1件は引けること(テストで確認される)。
- 絵は `docs/50-authoring/02-animation-guide.md` を見て board-artist に依頼する。

## 作る前に

**まず5件だけ作って見てもらう。** 方向が違っていたときに捨てる量を小さくするため。
過去に77都市を書いてから「多すぎた」となり、丸ごと捨てたことがある。

## 終わったら

```
node scripts/extract-legacy-content.mjs
npx vitest run src/infrastructure/content src/presentation/hooks
```

件数が意図どおりかを目で確認する。
