# 都市の背景そのものを描く

都市カードの絵は3層でできている。この文書は**いちばん下の静止した背景**の話。
上に重ねる動きの層は [05-city-scene-guide.md](./05-city-scene-guide.md) を見ること。

| 層 | 中身 | どこにある |
|---|---|---|
| 1. 背景 | 空・地形・町並み(静止) | `content.bg[キー]` |
| 2. シンボル | その都市の象徴を4.1倍 | `content.marks[キー]` |
| 3. 動き | 波・湯気・灯り | `city/scenes/<国>-<キー>.tsx` |

背景は**種類ごとの共用**で、1枚を最大11都市が使う。1枚直すと11都市が変わる。

---

## 1. 直す場所は国によって違う

| 国 | 場所 |
|---|---|
| india / france / world / ibaraki | `scripts/countries/<国>/art.mjs` の `BG` |
| **japan / bolivia** | `scripts/content-overrides/` に置いて `override.bg` で差し替える |

日本とボリビアの背景は `legacy/grand-express.html` に書かれているが、
**legacy は凍結しているので直接は書き換えない。**
`applyContentOverrides` の `bg` がキーごとに差し替えてくれる。

### 上書きは「文字列」か「関数」か

`override.bg` の値は2つの形を取れる。**用途で使い分ける。**

| 形 | いつ使うか | 例 |
|---|---|---|
| **文字列** | **描き直すとき**(元の絵を残さない) | `japan-city-bg.mjs` |
| `(prev) => next` | **元の絵を少しだけ直すとき** | `city-bg-gap-fixes.mjs` |

判断の分かれ目は **`--src` が使えるかどうか**。

`node scripts/check-city-backgrounds.mjs --src japan` は、生成物を焼き直さずに
元のモジュールを読んで塗り残しを実測する。**関数は元の絵が無いと評価できない**ので、
`--src` からは見えない(黙って飛ばすのではなく、対象外だと分かるようにしてある)。

そこでこう分けている。

- **描き直したもの**は文字列にする。描きながら `--src` を何度も回せることのほうが、
  差分の読みやすさより価値が大きい。**塗り残しは描いている最中にいちばん作る**
- **塗り残しを埋めるだけ**の直しは関数にする。丸ごと写すと1ファイル20KBになり、
  「どこを変えたのか」が追えなくなる。関数なら1行で済むし、
  こちらは絵を作り足していないので `--src` で見張る必要が薄い
  (生成物を見る通常の実行では、ちゃんと検査される)

関数側には**置換がちょうど1か所だけ当たることの検査**を入れてある。
legacy 側がずれたら、静かに効かなくなるのではなく抽出時に落ちる。

`src/infrastructure/content/*.content.json` は生成物。直接編集しない。
直したら `node scripts/extract-legacy-content.mjs` で焼き直す。

## 2. 守ること3つ

### 2.1 中央25%は描いても見えない

**これがいちばん間違えやすい。**

シンボルは 24×24 の図形を `s=4.1` 倍し、下端が `gy=152` に来るように置かれる
(`city-art.tsx`)。つまり**必ず x=151〜249 / y=54〜152 を覆う**。
影の楕円も (200,155) rx=53.3 ry=13.9 に載る。

```
        0        151          249        400
      0 ┌─────────────────────────────────┐
        │         │███████████│           │  ← ここに描いたものは
     54 │         │███████████│           │     シンボルの下敷きになる
        │         │███ 見え ███│           │
        │         │███ ない ███│           │
    152 │         └───●───────┘           │  ← 接地線 y=152
        │           影の楕円               │
    210 └─────────────────────────────────┘
```

見せたい細部は**左右3分の1**と、**y>170 の手前**に置く。

実際に踏んだ: アラビア海の港に沖の貨物船を x=176 に描いたら、**跡形もなく消えた。**
x=252 へ寄せて初めて見えた。軽トラを x=212 に置いたときも、白い切れ端しか見えなかった。

### 避けるのではなく、使う

この帯は「よけるべき障害」ではなく、**構図を決める手がかり**として使える。

**(a) 隠れる場所には、繰り返しの・失っても惜しくないものを置く。**

`lakepalace` は元は湖の真ん中に白い宮殿がひとつだったが、そこは真後ろで見えていなかった。
**楼閣を左右へ振り分け、あいだを低い列柱にした。**列柱は繰り返しなので、
中央が隠れても失うものが少ない。`desertfort` も城壁を横に長くして**櫓を両端**へ置いた。

**(b) `y>170` の中央は隠れない。いちばん目に入るので、主役を置く。**

シンボルの下端は y=152、影の楕円は y=169 まで。**その下の中央は空いている。**

| 背景 | y>170 の中央に置いたもの |
|---|---|
| `japan/seaside` | 干し網の櫓 |
| `india/ghat` | 水に流れる灯明 |
| `india/bazaar` | 香辛料の山 |
| `india/desertfort` | らくだの隊商 |
| `india/megacity` | 黄色いタクシーとオートリキシャ |
| `india/himalaya` | マニ石の壁 |

### 2.2 塗り残しを作らない

背景は「空の帯」と「地面の矩形」を別々に置くので、**両者のyが噛み合っていないと
横一文字の隙間ができ、カードの地色がそのまま透ける。**

2026-08-08 の計測では、**全77背景のうち30種・合計63,266px**で起きていた。

| 症状 | 例 |
|---|---|
| 空が浅い | `india/gopuram` 空は y=118 まで、地面は y=150 から → 32行ぶん透け |
| 地面が無い | `japan/metropolis` **地面が1枚も無く**、ビルのあいだが下端まで素通し(8,664px) |
| 2pxのずれ | `bolivia/whitecity` 空 y=132 まで / 地面 y=134 から |

`art.mjs` の `sky(top, bottom, to)` の **`to` に「次に来る塗りの開始y」を渡す。**
既定の118はすぐ下に地面が来る場合の値でしかない。

```js
gopuram: sky("#8fc4e8", "#d4ead8", 150) + ground(150, "#9ab45c") + ...
//                                  ^^^ 地面の開始位置まで塗り下ろす
```

**確認は目視ではなく実測でやること:**

```
node scripts/check-city-backgrounds.mjs                  # 全部(生成物を見る)
node scripts/check-city-backgrounds.mjs japan            # 1国だけ
node scripts/check-city-backgrounds.mjs --src world      # 焼き直さずに元を見る
node scripts/check-city-backgrounds.mjs --hidden japan   # 隠れる帯に置いた図形を挙げる
```

> **`--hidden` は §2.1 の「中央25%」用。**描いたあと自分の絵に対して回す。
> 過去に実際に消した8件で試して6件を拾えた。ただし**判定ではなく手がかり**で、
> 全80背景では149件出る。多くは「隠れても惜しくない繰り返し」か
> 「動きの層がそこを指している」もの。終了コードは変えない。

`--src` は `scripts/countries/<国>/art.mjs` を直接読む。
`extract-legacy-content.mjs` を回さずに済むので**描きながら何度でも回せる**し、
他の担当が `scripts/` を編集している最中に生成器を回してしまう事故も避けられる。

> **終了コードは `tail` や `head` に通すと消える。**
> `npm run check 2>&1 | tail -6` は常に0を返す(パイプの最後のコマンドの結果になる)。
> 落ちても気づけないので、結果を判定するときはパイプを外すこと。

マゼンタの台紙に描いて透けた画素を数える。
静的に `<rect>` を数える方法では見つからない(地面を `<path>` で描くシーンを
誤判定するうえ、図形の重なりで塞がっている箇所も判別できない)。

新しく描いた絵でも同じ穴を開けた。稜線の最下点が y=74 なのに空を y=62 までしか
塗っておらず、10px透けていた。**描いたら必ず通すこと。**

### 2.3 決定性

`extract-legacy-content.mjs` は背景を2回評価して**同じ文字列になることを検査する**。
`Math.random()` や日付を使わない。`Math.sin` のような純粋な計算はよい。

## 3. 「厚い絵」とは何か — 手本はリポジトリの中にある

**手本は `france` の背景。**他の盤面のおよそ3.5倍濃い。「共用しているから薄い」のではなく、
1枚あたりの密度の差だった。薄い背景を使う都市が316都市中213都市あった(2026-08-08)。

### **数字は渡さない。手順を渡す。**

かつてここに「france 98要素」という表があった。**あの数字を信じてはいけない。**

同じフランスの背景を、3つの作業で3つの違う数字で測っていた。

```
2026-08-08  この手引きの表           98    正規表現でタグを数えた
2026-08-19  取りまとめが渡した表      79    別系統の集計
2026-08-19  エジプトの担当の実測    73.5    DOMに描いて svg * を数えた
```

**どれも間違ってはいない。数え方が違うだけ。**ところが渡された側は絶対値として受け取るので、
「79に届いていないから薄い」といった判断が起きる。アフリカでもエジプトでも同じ混乱が出た。
どちらも担当のほうが先に気づいて指摘してきた。

**比べるときは、手本と自分の盤面を同じ実行の中で測ること。**

```js
// playwright でDOMに描き、svg * を数える。**正規表現では数えない**
// ({list.map()} で作った図形が抜けるため)
const count = await page.evaluate(() => document.querySelectorAll("svg *").length);
```

見るのは**自分の中央値 ÷ フランスの中央値**であって、絶対値ではない。
1.0前後なら手本に並んでいる。0.5なら半分の濃さしかない。

### **記号は、縮小したシートを開くまで完成ではない**

エジプトで、96pxで1枚ずつ見ても・コードを読んでも気づかなかった読めない記号が5種あった。
**同系色の面が隣り合うと、縮小したときだけ輪郭が消える。**

盤面上の記号は**直径19pxほどの点**にしかならない。**19pxと96pxを並べたシートを焼いて、
目で見ること。**数字にも、拡大表示にも出ない。

薄い絵に共通して欠けていたのは4つ。

### 3.1 層 — 3層では足りない

薄い絵は「空・遠景の山・地面」で終わっている。厚い絵は5〜6層ある。
`france/alps` の重ね順がそのまま手本になる:

```
空(2枚重ね) → 靄の帯 → 遠い峰+雪冠 → 索道(人工物) → 手前の稜線+森
→ 雪原+起伏 → 山小屋(丸太の目地・窓の灯り・雨戸) → 最前景の樅2本
```

最後の「最前景の樅」が効いている。**手前の大きなものが中景を部分的に隠すと、
一気に奥行きが出る。**

### 3.2 近景 — 画面の下1/4が単色になっていないか

薄い絵は手前が空白の帯になっている。フランスは手前に葡萄・パラソル・羊・木を置く。

### 3.3 人の気配 — 建物だけの町になっていないか

日本16種・インド13種には**人が1人もいなかった**。
フランスには牛・羊・船・車・ケーブルカー・パラソルがある。

20px前後の人を2〜3人置くだけで町が生きる。同時に**大きさが伝わる**ようになる
(石段を上る参拝者を置くと、崖の高さが分かる)。

### 3.4 時間 — 全部が真昼になっていないか

日本16種のうち夕景は `volcano`、夜は `metropolis` だけだった。
夕方・夜は色数を増やさずに雰囲気を変えられる。石窟寺院を真昼の茶色い壁から
夕方に変えただけで別物になった。

## 4. 実際に外したもの

**焼いて目で見るまで分からない。** 型検査もlintもテストも、絵が正しく見えるかは見ていない。

### 4.1 生きものと植物は、**シルエットにその特徴が出ているか**で決まる

いちばん多く描き直したのがここ。**5回外している。**

| 描いたもの | 何に見えたか | 足りなかったもの |
|---|---|---|
| 椰子(線を放射状に) | 針葉樹の枝 | 羽の切れ込み |
| 椰子(なめらかな葉身1枚) | バナナの葉 | 同上 |
| 黒松(楕円を等間隔に積む) | **串に刺したパンケーキ** | 重なりと枝 |
| らくだ(胴と脚をひと筆で) | 犬 | 背より上に出るこぶと首 |
| ヤク(輪郭をひと筆で) | ただの黒い塊 | 垂れ下がる長い毛と反った角 |

**部位に分けて描くだけでは足りない。**らくだは部位に分けた後もまだ読めなかった。
原因は「背の線より上に出ているものが何も無い」ことで、
**四つ足の獣一般**に落ちていた。

らくだの要点は
**「背の上に山が1つ、その前に首が斜めに立ち上がり、頭は背より高い」**。
頭が背より低い時点で、何の動物か決まらなくなる。

判断のしかたは1つだけ。**拡大して焼いて、名前を言えるか。**
「らくだのつもりで描いたもの」ではなく「らくだに見えるか」を見る。
カードの実寸(400px)でも同時に見ること。実寸では細部が全部つぶれ、
**輪郭しか残らない**。

### 4.2 **背景がいちばん明るい場面**では、建物を思い切って落とす

雪国の街で、家の壁を `#e6dfcd` にしたら**雪原(`#e8eef4`)に溶けて家が消えた。**
壁を `#c9bda4` まで落として、やっと建物として読めるようになった。

ふだんの絵は「空がいちばん明るく、地面が暗い」ので、建物は明るい色で浮き上がる。
**この関係が逆転する場面がある。**

| 場面 | いちばん明るいもの |
|---|---|
| 雪国(`japan/snowcity`) | 雪原 |
| 塩湖(`bolivia/salar`) | 塩の平原 |
| 砂漠(`india/desertfort` `world/desert`) | 砂 |
| 霧・靄(`india/teagarden`) | 霧の帯 |
| 凍原(`world/tundra`) | 雪と氷 |

こういう場面では、**明るい色を建物に使うと消える。**
地面より2段は落とすこと。空の色を基準に決めない。

### 4.3 額縁が主役を飲み込んだ

奥行きを出そうと最前景に椰子を左右2本+隅の葉4枚置いたら、画面の左1/3と右1/4が
葉で埋まり、**主役の中華網が完全に隠れた**。右1本+左上の葉1枚に減らして解決。

**額縁は隅だけ。**

### 4.4 等間隔の格子は岩に見えない

岩肌に等間隔の縦の節理と画面いっぱいの横縞を引いたら、岩ではなく**煉瓦塀**になった。
大きな面を斜めに切って明暗を分け、割れ目は不規則な長さ・角度で数本だけにする。

### 4.5 構図を変えると、上に重ねる「動きの層」が壊れる

**背景を厚くするだけなら層はずれない。構図を変えると壊れる。**

`japan/port` を「岸壁が手前・水が奥」に描き直したら、
`city/scenes/japan-port.tsx` の**小舟が岸壁の上に乗った。**
層を読むと、波を y=126 / 130 / 164 / 182 / 196、小舟を (346,172) に置いていて、
**「y=120 より下はぜんぶ水」という前提**で作られていた。元の背景がその構図だったからだ。

**層ではなく背景のほうを合わせた。**港を水越しに見る構図に直し、手前を水のまま残して、
人は左から突き出した桟橋に立たせた。

層は元の絵に合わせて作られている。描き直すときは
**層が「水だと思っている場所」「空だと思っている場所」を、そのまま残す。**
16種を描き直して、ずれたのはここ1件だけだが、
**合成して焼かなければ気づけなかった。**必ず §5 の合成を通すこと。

### 4.6 水に浮かぶものは、輪郭では決まらない

舟の船体を暗い塊で描いたら、**水面に開いた穴**に見えた。
舷を明るくすると容器には見えたが、**水の上にあるとまでは言えていなかった。**

決めているのは輪郭ではなく**前後関係**。3つ重ねると決まる。

1. **さざ波を遮る** — 波より後に描く。波が隠れていれば水面より手前にある(**これがいちばん強い**)
2. **舷の内側に暗い三日月** — へこんだ容器だと分かる(平らな板と区別がつく)
3. **真下に映り込みの筋** — 影ではなく縦に伸びる筋。映り込むものは水の上にある

`india/art.mjs` の `boat()` はこの3つを持っていて、
**さざ波を描いたあとに呼ぶ**約束になっている。順序を守らないと1つめが成立しない。

### 4.7 同系色の近景は地面のしみになる

最前景の岩を地面と同系色で描いたら岩に見えなかった。**地面より2段暗くする。**
([10-how-animations-are-made.md](./10-how-animations-are-made.md) §4.4 と同じ話。
同じ色の図形が隣り合うと1つの塊に見える)

## 6. 色

[10-how-animations-are-made.md](./10-how-animations-are-made.md) §9 と同じ。
平たい塗り、輪郭は暗色。ただし背景は絵1枚が大きいので、
**同じ用途でも明度を2〜3段に分ける**と層が見えるようになる
(遠い緑・中景の緑・手前の緑を同じ値にしない)。
