# 都市の背景そのものを描く

都市カードの絵は3層でできている。この文書は**いちばん下の静止した背景**の話。
上に重ねる動きの層は [05-city-scene-guide.md](./05-city-scene-guide.md) を見ること。

| 層 | 中身 | どこにある |
|---|---|---|
| 1. 背景 | 空・地形・町並み(静止) | `content.bg[キー]` |
| 2. シンボル | その都市の象徴を4.1倍 | `content.marks[キー]` |
| 3. 動き | 波・湯気・灯り | `city/scenes/<国>-<キー>.tsx` |

背景は**種類ごとの共用**で、1枚を最大11都市が使う。1枚直すと11都市が変わる。

---

## 1. 直す場所は国によって違う

| 国 | 場所 |
|---|---|
| india / france / world / ibaraki | `scripts/countries/<国>/art.mjs` の `BG` |
| **japan / bolivia** | `scripts/content-overrides/` に置いて `override.bg` で差し替える |

日本とボリビアの背景は `legacy/grand-express.html` に書かれているが、
**legacy は凍結しているので直接は書き換えない。**
`applyContentOverrides` の `bg` がキーごとに差し替えてくれる。

`src/infrastructure/content/*.content.json` は生成物。直接編集しない。
直したら `node scripts/extract-legacy-content.mjs` で焼き直す。

## 2. 守ること3つ

### 2.1 中央25%は描いても見えない

**これがいちばん間違えやすい。**

シンボルは 24×24 の図形を `s=4.1` 倍し、下端が `gy=152` に来るように置かれる
(`city-art.tsx`)。つまり**必ず x=151〜249 / y=54〜152 を覆う**。
影の楕円も (200,155) rx=53.3 ry=13.9 に載る。

```
        0        151          249        400
      0 ┌─────────────────────────────────┐
        │         │███████████│           │  ← ここに描いたものは
     54 │         │███████████│           │     シンボルの下敷きになる
        │         │███ 見え ███│           │
        │         │███ ない ███│           │
    152 │         └───●───────┘           │  ← 接地線 y=152
        │           影の楕円               │
    210 └─────────────────────────────────┘
```

見せたい細部は**左右3分の1**と、**y>170 の手前**に置く。

実際に踏んだ: アラビア海の港に沖の貨物船を x=176 に描いたら、**跡形もなく消えた。**
x=252 へ寄せて初めて見えた。

裏返すと、既存の絵が中央に主役を置いているぶんは丸ごと無駄になっている。

### 2.2 塗り残しを作らない

背景は「空の帯」と「地面の矩形」を別々に置くので、**両者のyが噛み合っていないと
横一文字の隙間ができ、カードの地色がそのまま透ける。**

2026-08-08 の計測では、**全77背景のうち30種・合計63,266px**で起きていた。

| 症状 | 例 |
|---|---|
| 空が浅い | `india/gopuram` 空は y=118 まで、地面は y=150 から → 32行ぶん透け |
| 地面が無い | `japan/metropolis` **地面が1枚も無く**、ビルのあいだが下端まで素通し(8,664px) |
| 2pxのずれ | `bolivia/whitecity` 空 y=132 まで / 地面 y=134 から |

`art.mjs` の `sky(top, bottom, to)` の **`to` に「次に来る塗りの開始y」を渡す。**
既定の118はすぐ下に地面が来る場合の値でしかない。

```js
gopuram: sky("#8fc4e8", "#d4ead8", 150) + ground(150, "#9ab45c") + ...
//                                  ^^^ 地面の開始位置まで塗り下ろす
```

**確認は目視ではなく実測でやること:**

```
node scripts/check-city-backgrounds.mjs          # 全部
node scripts/check-city-backgrounds.mjs japan    # 1国だけ
```

マゼンタの台紙に描いて透けた画素を数える。
静的に `<rect>` を数える方法では見つからない(地面を `<path>` で描くシーンを
誤判定するうえ、図形の重なりで塞がっている箇所も判別できない)。

新しく描いた絵でも同じ穴を開けた。稜線の最下点が y=74 なのに空を y=62 までしか
塗っておらず、10px透けていた。**描いたら必ず通すこと。**

### 2.3 決定性

`extract-legacy-content.mjs` は背景を2回評価して**同じ文字列になることを検査する**。
`Math.random()` や日付を使わない。`Math.sin` のような純粋な計算はよい。

## 3. 「厚い絵」とは何か — 手本はリポジトリの中にある

背景1枚あたりの要素数(2026-08-08 実測):

| 国 | 平均要素数 | 背景 | 都市 |
|---|---|---|---|
| **france** | **98** | 12種 | 50 |
| world | 68 | 12種 | 66 |
| japan | 36 | 16種 | 74 |
| ibaraki | 30 | 13種 | 36 |
| bolivia | 30 | 14種 | 30 |
| india | 28 | 13種 | 60 |

**フランスだけが3.5倍濃い。**「共用しているから薄い」のではなく、1枚あたりの密度だった。
薄い背景(45要素未満)を使う都市は316都市中213都市ある。

薄い絵に共通して欠けていたのは4つ。

### 3.1 層 — 3層では足りない

薄い絵は「空・遠景の山・地面」で終わっている。厚い絵は5〜6層ある。
`france/alps` の重ね順がそのまま手本になる:

```
空(2枚重ね) → 靄の帯 → 遠い峰+雪冠 → 索道(人工物) → 手前の稜線+森
→ 雪原+起伏 → 山小屋(丸太の目地・窓の灯り・雨戸) → 最前景の樅2本
```

最後の「最前景の樅」が効いている。**手前の大きなものが中景を部分的に隠すと、
一気に奥行きが出る。**

### 3.2 近景 — 画面の下1/4が単色になっていないか

薄い絵は手前が空白の帯になっている。フランスは手前に葡萄・パラソル・羊・木を置く。

### 3.3 人の気配 — 建物だけの町になっていないか

日本16種・インド13種には**人が1人もいなかった**。
フランスには牛・羊・船・車・ケーブルカー・パラソルがある。

20px前後の人を2〜3人置くだけで町が生きる。同時に**大きさが伝わる**ようになる
(石段を上る参拝者を置くと、崖の高さが分かる)。

### 3.4 時間 — 全部が真昼になっていないか

日本16種のうち夕景は `volcano`、夜は `metropolis` だけだった。
夕方・夜は色数を増やさずに雰囲気を変えられる。石窟寺院を真昼の茶色い壁から
夕方に変えただけで別物になった。

## 4. 実際に外したもの

**焼いて目で見るまで分からない。** 型検査もlintもテストも、絵が正しく見えるかは見ていない。

### 4.1 椰子の葉を2回描き直した

- 細い線を放射状に並べた → **針葉樹の枝**に見えた
- なめらかな輪郭の葉身1枚にした → **バナナの葉**に見えた
- 中肋に小葉を1枚ずつ生やした → やっと椰子になった

**椰子だと分かるのは羽の切れ込み。**輪郭ではなく構造を描く。

### 4.2 額縁が主役を飲み込んだ

奥行きを出そうと最前景に椰子を左右2本+隅の葉4枚置いたら、画面の左1/3と右1/4が
葉で埋まり、**主役の中華網が完全に隠れた**。右1本+左上の葉1枚に減らして解決。

**額縁は隅だけ。**

### 4.3 等間隔の格子は岩に見えない

岩肌に等間隔の縦の節理と画面いっぱいの横縞を引いたら、岩ではなく**煉瓦塀**になった。
大きな面を斜めに切って明暗を分け、割れ目は不規則な長さ・角度で数本だけにする。

### 4.4 同系色の近景は地面のしみになる

最前景の岩を地面と同系色で描いたら岩に見えなかった。**地面より2段暗くする。**
([10-how-animations-are-made.md](./10-how-animations-are-made.md) §4.4 と同じ話。
同じ色の図形が隣り合うと1つの塊に見える)

## 5. 確認のしかた

```
node scripts/check-city-backgrounds.mjs     # 塗り残しの実測(必須)
npm run dev
npm run shot -- <国> city                   # 盤面の中で、シンボルと合成した状態で見る
```

**シンボルと合成しないと判断できない。**単体で見ると、中央25%が隠れることも、
影の楕円と噛み合うかも分からない。

背景を全種類並べて見たいときは、`content.bg` を読んでHTMLのグリッドに流し込み、
playwright で撮るのが早い(1国あたり数秒)。

## 6. 色

[10-how-animations-are-made.md](./10-how-animations-are-made.md) §9 と同じ。
平たい塗り、輪郭は暗色。ただし背景は絵1枚が大きいので、
**同じ用途でも明度を2〜3段に分ける**と層が見えるようになる
(遠い緑・中景の緑・手前の緑を同じ値にしない)。
