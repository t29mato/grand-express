# 新しい盤面の作り方

韓国・トルコ・イタリア・ドイツ・イギリス・中国を並行して作ったときの手順と、
実際に踏んだ穴をまとめたもの。**次に作る人が同じ穴を踏まないため**に書いている。

## 1. 寸法を決める

```
BW = BH × (経度の幅 ÷ 緯度の幅) × cos(平均緯度)
```

**度数の幅を掛けるのを忘れて `BH × cos` としてはいけない。**フランスで実際にやって、
国の形が縦に1.5倍伸びた。**横長の国(トルコ・中国)で横長にならなかったら、まずこの式を疑う。**

大きさは**都市1つあたり約90k px²**に合わせる。これより詰めるとマーカーが団子になる。

| 盤面 | BW×BH | 都市 | 1都市あたり |
|---|---|---|---|
| フランス | 2160×2090 | 50 | 90k |
| 日本 | — | 74 | 86k |
| 韓国 | 1680×2150 | 40 | 90k |
| トルコ | 3020×1280 | 43 | 90k |

**都市数の上限は「38〜42」のような数ではなく、この密度のほうが本体。**
都市を増やしたければ盤面を広げればよい(イタリア45・イギリス44・中国48)。

## 2. `seg`(1マスあたりの目安距離)を実測で決める

`segmentCount(距離, 投影)` は `距離 / seg` を1〜9に丸める。**盤面が広いほど大きくする。**

トルコ(横3020)で韓国と同じ84のままだと、1路線に9マス(上限)が並んで数珠つなぎになる。
担当が全55路線の投影後距離を実測し、最長674px・5マス超が6本だったのを、
**seg=140にして5マス超0本**にした。参考: フランス84 / 世界一周150。

## 3. 8ファイルを書く

`scripts/countries/<id>/` に `index` / `cities` / `geography` / `quiz` /
`money-events` / `flavour` / `music` / `art`。**手本は `korea/` がいちばん新しい。**

厄災の絵は `src/presentation/components/events/dooms/<id>-*.tsx` に7枚。

## 4. 登録する(7箇所)

**ここを忘れると何も起きない。**焼かれないだけで目録に載らず、テストも見に行かないので
**黙って消える。**`node scripts/extract-legacy-content.mjs` は登録漏れを警告するので、
実行して確かめること。

1. `scripts/extract-legacy-content.mjs` — import と `AUTHORED_COUNTRIES`
2. `scripts/content-overrides/property-economy.mjs` — 通貨倍率
3. `src/infrastructure/content/json-country-content-repository.ts` — `LOADERS`
4. `src/infrastructure/audio/country-music-styles.ts` — `STYLE_LOADERS`
5. `src/infrastructure/content/item-effect-rules.ts` — アイテム9件
6. `src/infrastructure/content/season-and-doom-rules.ts` — 季節12ヶ月と厄災7件
7. `src/presentation/components/events/dooms/index.ts` — 絵7枚

**国名の一覧はもう書かなくてよい。**検査もテストも `ALL_COUNTRY_IDS`(焼き上がった目録)
から引くようにしてある。以前は同じ配列が6箇所に手書きされていた。

通貨倍率は**盤面のあいだの実質を為替1.8倍以内に詰める**(`property-economy.mjs` 参照)。
日本 ×10000(¥12,000,000スタート)を基準に、その通貨の対円レートで割り戻す。
ユーロ圏は ×100 で揃っている。

## 5. 測る

```
node scripts/extract-legacy-content.mjs        # 焼く(登録漏れも警告される)
node scripts/check-quiz.mjs <id>               # 答えの漏れ・言語の混入・偏り
node scripts/check-sea-routes.mjs <id>         # 船が陸を走る/線路が海に出る
node scripts/check-city-backgrounds.mjs        # 背景の塗り残し
npm run check                                  # lint・型・依存・テスト・build・E2E
npm run shot -- <id> overview                  # **撮った画像は必ず開いて目で見る**
```

## 実際に踏んだ穴

### 4言語の書き漏らし

**全員が踏んだ。**韓国は日本語を33都市ぶん、イタリアは29件落としていた。
`city-helpers.mjs` の検証が例外を出すので気づけるが、**1件ずつ直すより
全件を機械的に数えるほうが速い。**「`|` が3本あるか」で数えられる。

### `sky()` の第3引数

渡し忘れると空と地面の継ぎ目が透ける。茨城・韓国・イタリアで踏んだ。
**「次に来る全面塗りの開始y」と突き合わせて機械的に確かめる。**
イタリア担当はさらにマゼンタ台紙の上でPNG化して目視した(これが確実)。

### 背景の見えない帯

都市シンボルが4.1倍で重なるため、背景の**横151〜249・縦54〜152は見えない。**
そこに描き込んでも無駄になる。密度は下(y>170)と左右の端に置く。

密度の目安は**背景1枚あたり40要素**(韓国27=薄い、茨城30、イタリア48、フランス98)。

### 路線の幾何

船が陸を走り、線路が海に出る。**これは書いた人の手では測れない**(焼く必要があるため)。
登録側が `check-sea-routes.mjs` を回して差し戻す。

直しかたは4通り(端の入れ替え / 陸路にする / 航路にする / 中継の町を挟む)。
**端の入れ替えがいちばん安全**で、添字が動かないので他の路線に波及しない。
路線配列に**途中挿入してはいけない**(添字がずれると無関係な路線の折れ方とマスの種類が変わる)。

**スクリプトが出す「いちばん小さい数」を鵜呑みにしない。**実在するかどうかで決める。
青函トンネル・マレー半島の鉄道・マルマライは、**地図が正しく検査が間違う**例で、
`KEPT` に理由を書いて残してある。

### 伝説を事実として書く

アルベロベッロの「税吏が来る前に崩せる家」、ローテンブルクのマイスタートルンク。
**どちらも観光案内で繰り返されるが、史実として確かめられていない。**
遊びながら学ぶと謳っている以上、伝聞は伝聞と分かる形で書く。

### 領有権・係争のある土地

韓国では独島を、中国では台湾を**意図的に外している。**
デリー/ロンドンデリーのように**名称そのものが論点**の場合は併記する。
災害から間もない土地(アンタキヤ)は、何事もなかったような観光案内にしない。

## 並行して作らせるとき

- **共有ファイルは書いた人に触らせない。**同時に編集すると壊れる。
  登録内容は `scripts/countries/<id>/REGISTER.md` に貼れる形で書かせ、取りまとめ側が当てる
- **生成器(`extract-legacy-content.mjs`)を同時に走らせない。**
  作業ツリーを共有しているので、生成物が壊れる
- **`git commit` はパスを明示する**(`git commit -- <パス>`)。
  ほかの担当が `git add` した直後に打つと、その差分まで巻き込む(実際に起きた)
- 走査して自動で盤面を拾う形は**作って捨てた。**作りかけまで焼き込み、
  デプロイが作業ツリーをそのまま上げるため本番に出てしまう
