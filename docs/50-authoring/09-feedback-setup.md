# ご意見の受け付けを動かす手順

フィードバック画面(`/feedback`)は入っているが、**送り先が未設定のうちは
「準備中」と出るだけで何も送られない。** 動かすには次の2つを用意する。

## 1. issue専用の公開リポジトリを作る

**ソースコードのリポジトリ(`t29mato/grand-express`)は非公開のままでよい。**
公開するのは issue を置く場所だけ。中身は README 1枚で足りる。

```
gh repo create t29mato/grand-express-feedback --public \
  --description "Grand Express へのご意見・ご要望" \
  --add-readme
```

**なぜ別のリポジトリにするか。** 送った人が「あの要望はどうなったか」を
あとから見に来られるようにしたい。それには issue が公開されている必要がある。
かといってコードまで公開したくない。分ければ両方が成り立つ。

作ったら Issues が有効になっていることを確認する(既定で有効)。

## 2. トークンを Vercel に置く

GitHub の **fine-grained personal access token** を作る。

- Repository access: **上で作ったリポジトリだけ**を選ぶ
- Permissions: **Issues → Read and write** のみ。他は付けない
- 有効期限は付けておく(切れたら画面は「準備中」に戻るだけで、壊れはしない)

Vercel の Environment Variables に2つ入れる。

| 名前 | 値 |
|---|---|
| `FEEDBACK_REPO` | `t29mato/grand-express-feedback` |
| `FEEDBACK_TOKEN` | 上で作ったトークン |

`NEXT_PUBLIC_` を**付けないこと。** 付けるとブラウザに配られてしまう。

入れたら再デプロイすれば効く。

## 動いているかの確かめかた

1. `/feedback` を開いて1件送る
2. 完了画面に issue の URL が出る
3. その URL を**ログアウトした状態**で開く。読めれば公開になっている
   (読めなければリポジトリが非公開のまま)

## 荒らし対策として入れてあるもの

誰でも叩ける入口なので、`src/app/api/feedback/route.ts` に3つ入れてある。

- **文字数の上限**(題名120字・本文4000字)。長文を大量に貼られると読めなくなる
- **同じIPから1分に3件まで**。ただしサーバーレスなので実体は呼び出しごとに
  消えることがあり、**厳密な制限にはならない**。大半の連投は止まる、という程度
- **罠の入力欄**。画面上は見えない欄で、埋まっていれば自動投稿とみなして捨てる。
  断りの理由は返さない(仕組みを教えることになるため成功したように見せる)

本気で守るなら外部のストアや Turnstile が要るが、いまの規模では割に合わない。
荒らされ始めたら考える。

## 送られてくるもの

issue の題名は利用者が書いた1行、本文は詳細に加えて、
遊んでいた盤面と表示言語が末尾に付く(再現の手がかりになるため)。
種別に応じて `bug` / `idea` / `content` / `feedback` のラベルが付く。
