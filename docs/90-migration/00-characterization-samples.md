# 90-00. キャラクタライゼーションサンプル(現行コードの入出力仕様)

Phase 0.3の成果物。現行 `grand-express.html` の計算ロジックを、Domain層のユニットテストの
最初のRedケースとしてそのまま使えるよう、入出力サンプルを書き出したもの。**移行時はここに書かれた
数値と完全一致することを確認する**(挙動を変える場合は別Issueとして扱う)。

## 1. 物件の投資コスト `upCost(o, lv)`

```js
upCost = (o, lv) => Math.round(o.cost * 0.7 * lv / 10) * 10
```

`cost=300` の物件の場合:

| lv | upCost(300, lv) |
|---|---|
| 1 | 210 |
| 2 | 420 |
| 3 | 630 |
| 4 | 840 |

## 2. 物件のレベル別収入 `incAt(o, lv)`

```js
incAt = (o, lv) => Math.round(o.inc * (1 + 0.55 * (lv - 1)))
```

`inc=40` の物件の場合:

| lv | incAt(40, lv) |
|---|---|
| 1 | 40 |
| 2 | 62 |
| 3 | 84 |
| 4 | 106 |
| 5 | 128 |

## 3. 累計投資額 `investedIn(k, lv)`

```js
investedIn = (k, lv) => { let v = o.cost; for (l = 1; l < lv; l++) v += upCost(o, l); return v; }
```

`cost=300` の物件の場合:

| lv | investedIn(300, lv) |
|---|---|
| 1 | 300 |
| 2 | 510 |
| 3 | 930 |
| 4 | 1560 |
| 5 | 2400 |

## 4. 売却額 `sellValue(k, lv)`

sellValue = (k, lv) => Math.round(investedIn(k, lv) * 0.65 / 10) * 10

## 5. プレイヤー収入 `playerIncome(p)` と独占判定

```js
function playerIncome(p) {
  // 都市ごとにグルーピングし incAt を合算。
  // その都市の全物件を保有していれば合計を2倍(独占ボーナス)。
  // さらに地方の季節補正 mod[region] を掛ける。
}
```

- ある都市に3物件存在し、プレイヤーがLv1(inc=40)とLv2(inc=40→62)の2件のみ所有(独占ではない):
  `s = 40 + 62 = 102`、`mod=1` → 加算額 `102`
- 同じプレイヤーがその都市の残り1件(Lv1, inc=30)も購入して独占達成:
  `s = (40 + 62 + 30) * 2 = 264`、`mod=1` → 加算額 `264`
- 季節補正で地方の`mod`が`1.2`の場合: `264 * 1.2 = 316.8` → `Math.round` で合算 → `317`

## 6. 総資産 `netWorth(p)`

```js
netWorth = p => p.cash + Object.keys(p.props).reduce((s, k) => s + investedIn(k, p.props[k]), 0)
```

- `cash=1000`、物件A(cost=300, lv=3 → investedIn=930)のみ所有 → `netWorth = 1000 + 930 = 1930`

## 8. 経路探索 `bfsDist(from, to)`

隣接グラフ上の最短ホップ数(重み無し)。`from === to` の場合は `0`、到達不能の場合は `999`
(実際には全マスが連結しているため通常発生しない)を返す。

## 9. 中間マス生成のハッシュ関数 `h32`

各エッジの中間マスの種別(quiz/blue/red/card)は、決定的な32bitハッシュ `h32(ei*97+k)%20` で
以下のように振り分けられる(`ei`=エッジ番号, `k`=エッジ内の中間マス番号)。

| roll = h32(...) % 20 | 種別 |
|---|---|
| 0〜9 (10通り) | quiz(さらに `h32(ei*211+k*7)%3` でlow/mid/highを決定) |
| 10〜13 (4通り) | blue |
| 14〜16 (3通り) | red |
| 17〜19 (3通り) | card |

同一の `ei`, `k` の組であれば常に同じ結果になる(疑似乱数だが再現可能)。
移行後もこの `h32` 関数をそのまま移植し、**同じ国データ(edges)であれば同じ盤面が生成される**
ことをユニットテストでスナップショット確認する。
