# ADR-0006: 多言語対応は next-intl + ロケールJSONに置き換える

- ステータス: 承認(2026-08-05実装時に一部実用簡略化。下部の追記参照)
- 日付: 2026-08-05

## コンテキスト

現行実装は独自フォーマット `"英語|スペイン語|フランス語|日本語"` をパイプ区切り文字列で表現し、
`_t()` でパース、`tx()` で現在言語に応じた文字列を取り出している(`UI` オブジェクトに約140件、
加えて都市名・クイズ文・アイテム説明・季節イベント文などゲームコンテンツ内にも多数埋め込まれている)。

この方式の課題:
- 1文字列の中に4言語が同居しており、差分レビュー・翻訳漏れの検出がしづらい
- 型がないため、存在しないキーを参照してもビルド時に検出できない
- コンテンツデータ(都市/クイズ/アイテム)と翻訳文字列が同じオブジェクトに混在しており、
  ファイル肥大化の一因になっている

## 決定

- **next-intl** を採用し、UI文言は `src/i18n/messages/{en,es,fr,ja}.json` に分離する。
- ゲームコンテンツ(都市の紹介文・クイズ文・アイテム説明・季節イベント文)も同様にロケールごとの
  JSONへ分離し、`infrastructure/content/{country}/{locale}.json` のように
  コンテンツ本体(数値データ)と表示文言を分けて管理する。
- 移行時は現行の `_t("en|es|fr|ja")` 形式を機械的にパースしてロケール別JSONへ変換するワンショットの
  移行スクリプトを用意する(手作業での転記ミスを防ぐため)。
- URLロケール切り替えは `app/[locale]/...` のセグメントルーティングで表現する。

## 代替案

- **`react-i18next`**: 実績は十分だが、Next.js App RouterでのSSR/RSC対応は `next-intl` の方が親和性が高い。
- **独自フォーマットの型安全化のみ(ライブラリ導入せず)**: 差分レビューのしやすさや第三者ライブラリの
  エコシステム(複数形対応・日付/通貨フォーマットなど)を活かせないため見送り。

## 影響

- Domain層は翻訳を一切知らない(表示文言はPresentation層の責務)。ドメインイベントには
  「どの都市か(`CityId`)」「いくらか(`Money`)」といった値だけを持たせ、文言組み立ては
  Presentation側で `next-intl` のメッセージテンプレートに埋め込む。

## 実装時の追記(2026-08-05, Phase6実施時)

実際の実装では、以下2点を実用上の理由で簡略化した。

1. **ルーティングは行わない**: 本アプリは完全にクライアント完結のゲームで、原作でも
   言語切り替えはURLではなくその場でのトグルボタンだった(`LANG` はただのJS変数)。
   Next.jsの `app/[locale]/...` セグメントルーティング+ミドルウェアによる言語検出は
   このUXには過剰なため採用せず、`LocaleProvider`(React Context、
   `src/presentation/i18n/locale-context.tsx`)による**クライアント側の状態切替**のみ実装した。
   URLベースの多言語ルーティングが必要になった場合(SEO対策等)は別途ADRを起こすこと。
2. **UIメッセージの補間はnext-intlのICU構文を使わず、独自の位置引数(`{0}`,`{1}`)方式のまま**:
   `scripts/extract-legacy-content.mjs` で抽出したメッセージ文字列は、legacyの `T()`/`T2()` が
   使っていた `{0}` 形式のプレースホルダーをそのまま含んでおり(一部は `<b>`,`<span>` などの
   HTMLタグも埋め込み済み)、ICU構文への変換は追加のワンショット変換コストがかかる。
   実際の文言解決には `src/presentation/i18n/messages.ts` の `formatMessage()`
   (単純な `{n}` 置換)を使う軽量な自前実装で代替した。将来的に複数形・日付フォーマット
   などICU機能が必要になった時点で、メッセージ文字列をICU形式に変換し `next-intl` の
   `useTranslations` へ切り替える。
3. **`next-intl` パッケージ自体は依存から削除した(2026-08-05)**: 当初は依存として
   導入していたが、上記の通り実際には一度もimportしておらず、さらに `next-intl` が
   引き込む `@swc/core` の任意ピア依存(`@swc/helpers >=0.5.17`)が `next` の固定する
   `@swc/helpers@0.5.15` と衝突し、`npm ci` が「lockfileと package.json が同期していない」
   として失敗する原因になっていた(CIが継続的に赤くなっていた)。未使用であることを
   確認のうえ削除し、`npm ci` が通ることをクリーンな環境で検証した。
   将来ICU機能が必要になった時点で改めて導入する。

コンテンツデータ(都市名・クイズ文・アイテム説明等)についても、ADR-0007の追記の通り
ロケールJSONへの完全分離ではなく `{en,es,fr,ja}` インラインの簡略形にしている。
