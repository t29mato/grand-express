# ADR-0001: フロントエンドに Next.js を採用する

- ステータス: 承認
- 日付: 2026-08-05

## コンテキスト

現行の `grand-express.html` はビルドツールなしの単一HTMLファイル。ユーザーからの要望として
「フロントはNext.jsで良い」という指定があり、またルーティング(セットアップ画面/ゲーム画面/多言語URL)、
コード分割、型安全なReact開発基盤が必要。

## 決定

Next.js(App Router)を採用する。ただしゲームは完全にクライアント完結(サーバーでの状態保持は不要)なため、
ゲーム画面配下のコンポーネントは基本的に `"use client"` とし、Next.js は主に
「ファイルベースルーティング」「TypeScript/Reactの開発基盤」「将来のサーバー機能拡張の受け皿」として使う。

- `output: "export"`(完全な静的サイト出力)にはしない。将来サーバーサイドでのセーブデータ共有や
  ランキング機能を追加する余地を残すため、通常のNext.jsサーバーモードのままにする。
- 言語切り替えは `app/[locale]/...` のセグメントルーティングで表現する([ADR-0006](./0006-i18n-strategy.md))。

## 代替案

- **素のReact(Vite)**: ビルドは軽量だが、ルーティングや将来のサーバー機能拡張を自前で用意する必要があり、
  ユーザーの指定(Next.js)からも外れるため不採用。
- **静的サイト出力(`next export`)のみ**: ホスティングは単純化できるが、将来の拡張余地を狭めるため不採用。
  必要になった時点でいつでも切り替え可能。

## 影響

- ゲームロジック(Domain/Application層)はNext.js/Reactに依存しないため、将来フレームワークを
  変更する場合もロジック資産は流用できる。
- 開発環境として Node.js + TypeScript + Next.js のビルドチェーンが必要になる(現行はブラウザのみで動作していた)。
