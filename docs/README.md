に基づいて **Next.js** アプリへ移行するための設計資料一式です。

現行実装の分析結果に基づいて作成しています。読む順番は番号どおりを推奨します。

## サマリー

- **現状の課題**: 1ファイルにゲームロジック・DOM操作・描画・音声・翻訳文字列・保存処理・コンテンツデータ(都市/クイズ/アイテム)が全部同居しており、保守性が低く、LLMに1タスク依頼するたびにファイル全体(385KB)をコンテキストに読ませる必要があり、トークン消費が非常に大きい。
- **狙い**: ドメインロジックを純粋なTypeScriptの Domain 層に切り出し、責務ごとに小さなファイル(目安200〜300行)に分割することで、①保守性を上げる ②テストを書けるようにする ③LLMに変更を依頼するときに読み込む範囲を最小化してトークン消費を大きく削減する。
- **この資料セットのゴール**: 実装に入る前に、アーキテクチャ・ドメインモデル・テスト方針を固め、移行作業を安全に分割できるWBSを用意すること。**このドキュメント一式では実装(Next.jsプロジェクトの雛形作成やコード移植)はまだ行っていません。** WBSはその後続作業の計画です。
