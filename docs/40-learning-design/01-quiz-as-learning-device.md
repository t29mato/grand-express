# 40-01. クイズを「学習装置」として機能させる

## 1. 前提: このゲームの目的

本作の目的は **プレイヤーの学習**（対象国の地理・歴史・文化）である。勝敗や資産形成は
学習を続けさせるための動機づけであり、目的そのものではない。したがって設計上の判断は
「どちらが楽しいか」より前に **「どちらが記憶に残るか」** で決める。

この前提に照らすと、現状のクイズは学習装置として機能していない。以下、コード上の根拠と
改善案を示す。

## 2. 現状の問題

### 2-1. 【致命的】人間プレイヤーには正解も解説も表示されない

`src/presentation/state/game-store.ts` の `answerQuizOption` は、回答した瞬間に
`ui: { kind: "idle" }` へ遷移する。プレイヤーに残る情報は効果音とログ1行
（`quizOkLog` = 「❓ **You** がクイズ正解 (+100)」）だけである。

`src/presentation/components/modals/quiz-modal.tsx` は `question.fact`（解説文）を
一切描画していない。つまり **間違えても「何が正解だったのか」すら分からない。**

さらに悪いことに、`src/presentation/components/modals/cpu-quiz-modal.tsx` は
CPUの手番で「豆知識」を表示している。**何も学ばないCPUには解説が出て、学ぶべき人間には
出ない** という逆転が起きている。

> フィードバックのない出題は学習にならない。「思い出そうとする→正誤と理由を知る」の
> 2つが揃って初めて記憶に定着する。現状は前半しかない。

### 2-2. 出題が復元抽出（同じ問題が連続で出る）

`src/presentation/state/game-store-turn-flow.ts` は
`context.content.quiz[random.nextInt(context.content.quiz.length)]` で毎回引いている。
直前に出た問題がすぐまた出る。

一方 `src/domain/quiz/quiz-grading-service.ts` の `QuizDeck`（シャッフルした袋から引き、
尽きたら再構築する＝重複なし）は **実装もテストも済んでいるのに、どこからも呼ばれて
いないデッドコード** になっている。

### 2-3. 復習の仕組みがない

間違えた問題は記録されない。ゲーム終了時のまとめもない。次に同じ問題に出会っても
「前回間違えた」という情報がどこにもない。

### 2-4. お守りアイテムが学習信号を消している

`src/application/use-cases/answer-quiz/answer-quiz.use-case.ts` の `quiz-save` 効果は、
不正解を **無条件で正解に変換し、賞金も満額** 与える。プレイヤーは自分が間違えたことを
認識しないまま先に進む。ゲーム的な救済としては妥当だが、学習的には最悪の挙動である。

### 2-5. 難易度と問題内容が無関係

`QuizTier`（low/mid/high、賞金100/190/320）は **盤面のマスの属性** であって問題の属性では
ない。`QuizQuestion` に難易度フィールドが存在しないため、「高額の問題」マスで
「日本最高峰は？」のような易しい問題が出る。学習の階段が作れない。

### 2-6. 問題数が足りない

ボリビア39問＋日本32問＝**71問**。1ゲームでクイズマスに十数回止まるため、2〜3ゲームで
一巡する。教材としては桁が1つ足りない。

## 3. 評価できる点

- **問題文と解説の質は高い。** 単なる暗記ではなく因果を説明する書き方になっている
  （例:「ボリビアはチリに海岸を奪われたが、今も海軍を保持しチチカカ湖で訓練。
  毎年3月23日は『海の日』」）。
- **本当の学習の主軸は盤面である。** 桃鉄が地理教材として機能している理由はクイズでは
  なく、「都市名を何度も通り、物件を買い、位置関係を体で覚える」ことにある。本作には
  `city.fact` があり `city-modal.tsx` で既に表示されている。地形マップ・地方区分・
  季節イベントも実装済みで、ここは既に強い。

**資産は既にあり、プレイヤーに届いていないだけ。** よって改善はコンテンツ追加ではなく、
まず「届ける配線」から着手する。

## 4. 改善案

優先度順。1が単体で効果の大半を占める。

### 案1. クイズ結果モーダル 【最優先】

回答後に結果モーダルを挟み、**正解の選択肢・自分が選んだ選択肢・増減額・解説(`fact`)** を
表示する。

- `game-store-types.ts` の `UiState` に `quiz-result` を追加する。
- `quiz-result-modal.tsx` を新規作成する。**`cpu-quiz-modal.tsx` をほぼ流用できる**
  （情報構造が同じ）。差分は、自分の選択と正解を両方示し、不正解時に正解側を強調すること。
- `answerQuizOption` は `idle` ではなく `quiz-result` をセットし、
  `finishHumanLandingAndAdvance()` の呼び出しはモーダルを閉じるアクションへ移す。
- i18n は `didYouKnow` / `correctPlus` / `wrongMinus` / `continue` / `quizLow|Mid|High` を
  再利用できる。新規キーは「正解は {0} でした」1つのみ（en/es/fr/ja の4ファイル）。

### 案2. `QuizDeck` を実際に使う

- `game-store-turn-flow.ts` の `random.nextInt` 直引きを `QuizDeck.draw()` に置換する。
- デッキは **1ゲーム＝1インスタンス**。国を切り替えたら作り直す必要があるため、
  ゲーム開始時に生成してストアに保持する。
- **人間とCPUで同じデッキを共有する。** 袋を分けると重複が戻る。
- セーブ/ロード時にデッキ状態を復元する必要はない（ロード後は袋が再構築されるだけ）。
  ADR 0005 のセーブ形式は変更しない。

### 案3. 間違えた問題の記録と、終了時のおさらい

- `src/domain/quiz/learning-record.ts` を新設し、`missedQuestions` を保持する純関数
  （`recordMiss`）を置く。**学習が本作の主目的である以上、学習記録はドメイン概念** である。
- `GameSession` に `learningRecord` を持たせ、`answer-quiz.use-case.ts` の不正解パスで更新する。
- ゲーム終了モーダルに「今回のおさらい」として、間違えた問題の問題文＋正解＋解説を並べる。
  リストが空ならセクションごと出さない。
- **同一画面で複数人がプレイする都合上、おさらいは全員分をまとめて出す。** 誰がどれを
  間違えたかまで出すと角が立つ場面があるため、問題単位でまとめるのが無難
  （[40-02](./02-player-knowledge-level.md) の想定プレイ環境を参照）。

### 案4. お守りアイテムの意味を変える

「不正解の扱いは変えず、損失だけ無効化する」に変更する（`savedByCharm` 時は増減額0、
賞金なし、正解としてカウントしない）。結果モーダルでは正解と解説を通常どおり見せた上で
「お守りが損失を防いだ」と表示する。

> これは legacy（`legacy/grand-express.html`）の挙動からの **意図的な逸脱** になる。
> 実施する場合は `docs/90-migration/03-as-built-status.md` に「移行後の仕様変更」として
> 記録すること。legacy との挙動一致を優先する方針なら、この案だけ見送ってよい。

### 案5. プレイヤーごとの知識レベル 【別ドキュメント】

国際色豊かなメンバーでプレイする際、対象国の出身者と初見のプレイヤーでは前提知識が
まったく違う。→ [40-02. プレイヤーごとの知識レベル](./02-player-knowledge-level.md)

## 5. 今回スコープ外（将来課題）

| 項目 | 理由 |
|---|---|
| 問題数の増量（目標: 各国150問以上） | 4言語×事実確認が必要で、コード変更とは作業の性質が異なる。先に `raw-content-schema.ts` へ `source`（出典）フィールドを追加し、出典を記録する運用を決めてから着手する |
| 問題側への `difficulty` 付与と、マスのtierとのマッチング（2-5の解消） | 既存71問すべての難易度分類が必要。上記の増量とセットで行うのが効率的 |
| 間違えた問題の再出題（間隔反復） | 学習効果は最も高いが、セーブ形式（ADR 0005）の変更を伴う。案1〜3が入ってから検討する |

## 6. 検証方針

1. `npm run ci`（vitest / lint / typecheck / depcruise）。
   特に **depcruise**: `learning-record.ts` は domain 層なので外向き依存を持たせないこと。
2. `e2e/playwright/full-turn-loop.spec.ts` を拡張し、**クイズに不正解した後に結果モーダルが
   出て、正解の選択肢と解説文が表示される** ことを検証する。
3. `npm run dev` で1ゲーム通しでプレイし、以下を目視確認する。
   - 不正解時に正解と解説が読めること
   - 同じ問題が連続で出ないこと
   - 終了モーダルのおさらいに、間違えた問題だけが並ぶこと
